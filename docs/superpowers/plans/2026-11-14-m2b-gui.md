# M2b — The gpui client: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS app, `fleet-gui`, that the user can daily-drive for Claude Code sessions:
- a sidebar of every agent and up to 4 split panes;
- terminal panes faithful enough for Claude Code, with the whole conversation scrollable;
- a connect sheet for a local or a remote fleetd;
- a menu-bar item that keeps the app and its attachments resident;
- wall benchmarks for cold start and input-to-render.

**Architecture:**
- `fleet-gui` has two layers. The **core** (`src/core/`) is plain Rust with no gpui, compiled and tested on macOS and Linux:
  - config and saved state;
  - connection targets and the local daemon launcher;
  - key and mouse encoding;
  - the pane model (client grid plus history list plus selection);
  - the session layer (threads, connections, reconnects);
  - the split layout and the sidebar grouping.
- The **shell** (`src/app/`, `#[cfg(target_os = "macos")]`) is the gpui views, the terminal element and the AppKit status item. It only renders core state and turns gpui events into core calls.
- **Threading:**
  - each pane's connection has a reader thread that parses output into the pane model, behind a `Mutex`, off the UI thread, then wakes the UI through an async channel;
  - the UI renders at most once per frame from whatever is in the model;
  - input goes to a per-connection writer thread, so the UI thread never blocks on a socket.

**Tech Stack:**
- Rust 1.99.1 and gpui 0.2.2 (crates.io, precompiled Metal shaders);
- objc2 0.6 / objc2-app-kit 0.3 / objc2-foundation 0.3 for `NSStatusItem` and the activation policy;
- async-channel, toml / toml_edit and serde;
- `fleet-term`, `fleet-client` and `fleet-proto` from M2a.

## Global Constraints

- **Toolchain and lints:** toolchain `1.99.1`; `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` clean on macOS **and** Linux; deps via `cargo add`, no git deps.
- **Commits:** branch `m2b`, never push to main. No `Co-Authored-By` and no `Perf-Approved` trailers.
- **gpui and AppKit dependencies:**
  - `gpui = "=0.2.2"` with default features (precompiled shaders). This needs the Metal toolchain (`xcodebuild -downloadComponent MetalToolchain`), which the user installs on this Mac, the perf-wall runner. Do not use `runtime_shaders`: it compiles shaders at every launch and threatens the 200 ms cold-start budget. If the build fails with "missing Metal Toolchain", report BLOCKED; never install it yourself.
  - Dev-dependency: gpui with `test-support`.
  - `objc2 = "0.6"`, `objc2-app-kit = "0.3"`, `objc2-foundation = "0.3"`, the versions already in gpui's tree.
  - All of these go under `[target.'cfg(target_os = "macos")'.dependencies]`. The core uses none of them.
- **Linux:** `cargo build`, `clippy` and `test` for the whole workspace still pass on Linux. There `fleet-gui`'s `main` prints `fleet-gui is macOS-only` and exits 1.
- **Never copy Zed's `terminal` or `terminal_view` code** (GPL-3.0). gpui itself is Apache-2.0.
- **Anti-goals (spec):**
  - the GUI never reads the node's files directly; everything goes through the protocol;
  - the GUI never starts a daemon without asking;
  - agents keep running when the GUI quits or crashes. Quit and pane close only detach; only Kill kills.
- **Connections:**
  - one connection per visible pane, client name `gui-pane-<n>` (ADR 0022);
  - one control connection, client name `gui`, for listing, activity, spawn and kill;
  - handshake timeout: 10 s locally (`fleet_client::HANDSHAKE_TIMEOUT`) and `SSH_HANDSHAKE_TIMEOUT = 30 s` over ssh.
- **ssh argv:** `ssh -o ControlMaster=auto -o ControlPath=<state-dir>/ssh/%C -o ControlPersist=60 <dest> sh -lc 'exec fleetd --stdio'`. Sharing one ControlMaster keeps 5 connections on one TCP link. `sh -lc` lets `~/.cargo/bin` on a login PATH resolve.
- **Config** in `<state-dir>/config.toml` (default `~/.fleet`), table `[gui]`. The GUI writes only `connection`, using `toml_edit` so the user's comments survive.

  | key | type | default |
  |---|---|---|
  | `connection` | `"local"` or `"ssh://user@host"` | absent |
  | `default_command` | array of strings | `["claude"]` |
  | `font_family` | string | `"Menlo"` |
  | `font_size` | number | `13` |
  | `option_as_meta` | bool | `true` |
- **GUI-owned state** in `<state-dir>/gui-state.toml`, mode 0600:
  - `recent_targets`, at most 10, most recent first;
  - `recent_dirs`, at most 20 per target;
  - `layouts`, one per target string: the split tree and the agent id in each pane.

  Writes are atomic (temp file plus rename) and debounced by 500 ms.
- **Splits:**
  - `MAX_PANES = 4`; pane numbers 1–4 in reading order (top-left first);
  - `cmd-d` split right, `cmd-shift-d` split down, `cmd-w` close pane (detach), `cmd-alt-left/right/up/down` move focus, `cmd-1`…`cmd-4` focus a pane, `cmd-n` new agent, `cmd-c` copy (when there is a selection), `cmd-v` paste.
- **Timings:**
  - resize debounce `50 ms`;
  - reconnect backoff 250 ms, doubled after each failure, capped at 5 s, reset after a successful connect;
  - sidebar `ListAgents` re-list every 5 s, plus at once on an `AgentActivity` or `AgentExited` for an unknown id.
- **History paging:**
  - `HISTORY_PAGE_LINES = 1000` per `ReadHistory`;
  - fetch the next page when the view's top is within `PREFETCH_LINES = 200` of the oldest loaded line;
  - at most one page request in flight per pane;
  - history lines are stored as their raw ANSI bytes and parsed only when drawn.
- **Keyboard:**
  - **Supported kitty flags:** `KITTY_SUPPORTED_FLAGS = 0b1` (disambiguate only). Replies to `CSI ? u` are masked to these flags.
  - **Shift+Enter:** `\x1b[13;2u` when disambiguate is on, otherwise `\x1b\r`.
  - **Option-as-Meta** (default on): Option+key sends `ESC` followed by the key's base character.
- **Theme:** one dark and one light palette, following the window appearance (`WindowAppearance::Dark | VibrantDark` → dark). Queries for OSC 10, 11 and 4 are answered from the active palette.
- **Perf rule (CLAUDE.md):**
  - if an existing gated metric regresses, stop and report the before/after numbers;
  - never change existing baselines, tolerances or report-only flags, and never write `docs/perf-log.md`;
  - don't run the wall suite while a `perf-wall` CI job is running (`gh run list --workflow ci.yml --status in_progress`).
- **Gate code:**
  - Gate code is `crates/fleet-perf/src/{baseline,approval,wall,instr,lib,results}.rs`, `src/wall/*`, `src/bin/fleet-perf.rs`, `benches/instr.rs`, `crates/fleet-perf/Cargo.toml`, `.github/workflows/` and `rust-toolchain.toml`.
  - Touch it only in Task 13, additively.
  - New metrics: `gui_cold_start_ns` (budget 200 ms), `input_to_render_ns` (budget 16 ms) and `input_to_render_flood50_ns` (budget 16 ms). They start at `baseline = 0`, to be recorded from CI.

## Review Focus

1. **Claude Code starting in a GUI-spawned pane.** It queries kitty flags (`CSI ? u`), the background colour (`OSC 11 ; ? ST`) and the cursor position before drawing. The primary pane must answer all three promptly and exactly once. Pinned in Task 1 by `client_terminal_answers_kitty_and_color_queries`, and in Task 6 by `spawn_attached_pane_answers_startup_queries`.
2. **Re-attach after `Lagged` or a reconnect.** The pane rebuilds from the new `AttachOk`, and every history line appears exactly once, with no duplicates of what was shown before. Pinned in Task 5 by `reattach_replaces_history_without_duplicates`.
3. **Typing into a pane while its agent and three others flood.** Every keystroke arrives, in order, and the UI never blocks on a socket write. Pinned in Task 6 by `input_order_preserved_under_flood`.
4. **Clear-scrollback while a history page request is in flight.** The stale page, of the old generation or answered with a stale-generation `Error`, is dropped and never shown above the cleared view. Pinned in Task 5 by `page_arriving_after_clear_is_dropped`.
5. **A remote host without `fleetd`.** ssh exits 127 or prints `not found`, and the connect sheet says "fleetd is not installed on <host>" instead of "protocol error". Pinned in Task 3 by `ssh_exit_127_maps_to_fleetd_not_found`.

### Task 4: Key and mouse encoding

These are pure functions with no gpui types. The shell maps a gpui `Keystroke` to `Key` (Task 8).

**Files:**
- Create: `crates/fleet-gui/src/core/keys.rs`, `src/core/mouse.rs`

**Interfaces:**
- Produces:
  - `pub enum KeyCode { Char(char) /* the base, unshifted-by-option char as gpui's key */, Enter, Tab, Backspace, Escape, Up, Down, Left, Right, Home, End, PageUp, PageDown, Insert, Delete, F(u8) /* 1..=12 */ }`.
  - `pub struct KeyMods { pub shift: bool, pub alt: bool, pub ctrl: bool }`. Cmd is never encoded; the shell treats cmd-keys as app shortcuts.
  - `pub struct Key { pub code: KeyCode, pub mods: KeyMods, pub text: Option<String> /* gpui key_char: the layout's composed text */ }`.

### Task 5: Pane model

    - on EOF or an error: `on_disconnected`, then reconnect with `Backoff` and re-attach.
