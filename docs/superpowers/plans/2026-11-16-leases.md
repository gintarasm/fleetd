# M3-F leases — implementation plan

Spec §4, ADR 0077, issue #107. Test-first, small commits.

1. **Store (schema v10).** `leases` table (spec §4 columns); `holder_conn` holds the client's *holder key* (a random id the CLI picks once per `--` command), which is what lets a reconnecting CLI reclaim its lease after a daemon restart. Store methods: upsert, delete, all, delete-where-holder-not-running.
2. **State machine** `fleet_node::lease::Leases` (sync, no timers; time and load are arguments so tests are deterministic): acquire (grant / busy / load-too-high / queue), release, `conn_closed`, `agent_gone`, `tick(now, load)` (TTL expiry, orphan grace, FIFO grants), `next_wake`, `list`.
3. **Proto** (field block 65–69): `AcquireLease=65`, `ReleaseLease=66`, `ListLeases=67`; responses `LeaseGranted=65`, `LeaseList=66`, `LeaseInfo`.
4. **fleetd:** scope-table rows (allowed, explicit), request handlers (a waiting acquire answers from a spawned task so the connection keeps reading and notices a close), `Connection::drop` releases, a driver task (sleeps until the next deadline; one tick per second only while a waiter has `--max-load`), agent-exit hook.
5. **CLI** `crates/fleet-cli/src/lease.rs`: `fleet lease <name> … -- cmd`, `acquire`, `release`, `ls [--json]`, `--ttl` parser, exit codes, reclaim after a daemon restart.
6. **Tests:** unit (store, state machine, ttl parser), daemon integration (protocol level), CLI integration (`--` form, wait, restart survival).
7. **ADR 0077**, PR body with the "For the user" gate-file diffs (`.github/workflows/ci.yml`, `crates/fleet-perf/src/wall.rs`), not applied.
