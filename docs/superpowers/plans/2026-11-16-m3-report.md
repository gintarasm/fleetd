# M3-D: `fleet report` and the inferred status — plan

Issue #105, spec §2, ADR 0075. Proto block 50–54, schema v11.

1. **Shared inferred status** in `fleet_proto::status` (fleet-node depends on fleet-proto only): `AgentStatus`, `looks_like_prompt`, `inferred_status(info, last_line, last_output_ms, rang, now, quiet_ms)`. GUI `core::status` re-exports and keeps its `AgentRow` wrapper. Existing tests move with the code.
2. **Proto**: `Request.report = 50` (`ReportStatus`), `Event.reported = 50` (`AgentReported`), `AgentInfo.reported = 50` (`Reported`), `ReportedState` enum.
3. **Store v11**: columns `reported_state`, `reported_message`, `reported_unix_ms` on `agents`; `set_reported`; read into `AgentRecord`.
4. **Node**: `report(caller_agent, state, message)` validates (≤200 chars, running, not a shell), stores, emits `AgentReported`; `agent_info` fills `reported`.
5. **Server/scope**: request row (agent: self only, user: `forbidden:`), event forwarding through `Scope::sees`.
6. **CLI**: `fleet report` in `fleet-cli/src/report.rs`; `fleet ls` and `fleet tree` show reported status.
7. **GUI**: `card_dot` and sidebar dot use `reported` (solid) over inferred (hollow); `AgentReported` events update `infos`.
8. ADR 0075, tests, clippy, fmt, PR.
