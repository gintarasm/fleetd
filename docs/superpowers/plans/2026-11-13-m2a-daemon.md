# M2a — Daemon side of the gpui client: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything the M2 GUI needs from the daemon and CLI, usable and testable without a GUI. That covers:
- whole-conversation history served from the node (an in-memory tail plus on-disk pages);
- protocol v2 (`ReadHistory`, per-agent `Lagged`, `AgentActivity`, primary client, spawn-and-attach);
- the 4-attached-under-flood fix;
- the shared `fleet-term` and `fleet-client` crates;
- `fleetd --stdio` and login-shell environment capture;
- `fleet history`/`screen`/`ls --json`/`spawn --cwd`;
- the agent skill with `fleet skill install`.

**Architecture:**
- `fleet-term` (moved out of `fleet-node`) turns rows that scroll off the grid into ANSI history lines, and detects `CSI 3 J`.
- `fleet-node` stores those lines in a per-agent `History`: a 256 KiB in-memory tail plus segmented files capped at 64 MiB, with clear generations. It serves them in `AttachOk` and `ReadHistory`.
- `fleetd` speaks `PROTOCOL_VERSION = 2`.
- `fleet-client` is the blocking client over any byte stream, used by the CLI now and the GUI in M2b.

**Tech Stack:** Rust 1.99.1, alacritty_terminal 0.26 (public API only, ADR 0020), prost/protox, tokio, rusqlite, clap, serde_json (CLI `--json`).

**Spec:** `docs/superpowers/specs/2026-11-13-m2-gui-design.md`, §1–4, §5 "Connection" and "Agent environment", §6, §6a, §7 (daemon metrics), and "Decided after the builder check". M2b (the GUI) gets its own plan.

- **History constants:**

- **Agent env, in precedence order (lowest first):**
  1. the captured login-shell env (or the daemon's own env if capture fails or times out, 5 s);
  2. `TERM=xterm-256color` unless already set;
  3. `FLEET_AGENT_ID=<id>`;
  4. `SpawnAgent.env`.
- **Readiness:** env capture must not delay socket readiness (`fleetd_cold_start_ns`).
- **Platforms:** macOS and Linux for every crate in this plan.

## Review Focus

1. **A long Claude session** (thousands of lines, wrapped long lines, colours) followed by a re-attach must show every line exactly once, in order: tail, then disk pages, then the screen. Pinned in Task 4 by `attach_tail_pages_and_screen_reconstruct_all_lines`.
2. **Clear-scrollback (`CSI 3 J`)** mid-session, split across reads, or arriving in the same chunk as scrolled lines. Lines from before the clear are never served and lines after it are. Pinned in Task 2 by `clear_in_same_chunk_orders_lines_and_clear` and `clear_split_across_feeds_is_detected`, and in Task 3 by `read_after_clear_serves_only_new_generation`.
3. **Daemon restart.** History of agents from the previous run (`lost`/`exited`) is still readable with `ReadHistory`, and a stale generation is rejected. Pinned in Task 4 by `history_survives_daemon_restart`.
4. **Two clients on one agent.** Only the primary's resize applies, roles move on input, and both get `AttachRole`. Pinned in Task 6 by `primary_moves_on_input_and_only_primary_resizes`.
5. **Login shell that hangs or prints noise.** The daemon is ready immediately, the capture times out at 5 s, and agents fall back to the daemon env. Pinned in Task 8 by `noisy_or_hanging_login_shell_falls_back`.

### Task 2: History capture in `Terminal`

**Files:**
- Create `crates/fleet-term/src/{history.rs, scan.rs}`.
- Modify `crates/fleet-term/src/lib.rs`.
- Tests: unit tests in those files.

**Interfaces (Produces):**
- `pub enum HistoryEvent { Line(Vec<u8>), Cleared }`.
- `Terminal::drain_history(&mut self) -> Vec<HistoryEvent>`: events since the last call, in stream order.
- **Line rendering:** each `Line` is one grid row rendered as ANSI. It starts from the default pen, uses the snapshot's SGR rendering (shared code in `history.rs`, not duplicated), trims trailing default blanks, and ends with `\x1b[0m` if the pen is not default. No newline.
- **`HistoryEvent::Cleared`** is emitted for `CSI 3 J` (parameter exactly `3`) seen on the primary screen.

**Capture mechanism:**
- `Config::scrolling_history` becomes `HISTORY_SLACK = 10_000` rows.
- `feed` processes input in pieces of at most `FEED_PIECE = 4096` bytes. After each piece, rows in `grid().history_size()` are rendered oldest first (`Line(-(n as i32))` … `Line(-1)`), then `grid_mut().clear_history()`.
- `feed` also splits at the end of each `CSI 3 J` found by `scan.rs` (which tracks sequences split across `feed` calls). Lines scrolled before the clear are drained before `Cleared` is pushed.
- History is never captured while the alt screen is active (alacritty keeps none there).

### Task 3: `History` store (tail, segments, generations)

**Files:**
- Create `crates/fleet-node/src/history.rs`.
- Tests: unit tests.

**Interfaces (Produces):**
- `History::create(dir: &Path) -> io::Result<History>` (new agent, dir 0700) and `History::open(dir: &Path) -> io::Result<History>`. `open` rebuilds the sparse index by scanning segments; it is called lazily for exited/lost agents.
- `History::push(&mut self, line: &[u8])` and `History::clear(&mut self)`. `clear` bumps the generation and sets `first_line = next_line`.
- `History::tail(&self) -> (u64 /*first_line*/, Vec<Bytes>)`.
- `History::info(&self) -> HistoryInfo { first_line: u64, next_line: u64, generation: u64 }`.
- `History::read_page(&self, generation: u64, before_line: u64, max_lines: u32) -> io::Result<Page { first_line: u64, lines: Vec<Bytes> }>`:
  - returns the lines immediately before `before_line`, capped at `HISTORY_PAGE_MAX_LINES` and `HISTORY_PAGE_MAX_BYTES`, never below `first_line`;
  - a stale generation is an `io::ErrorKind::InvalidInput` error `"history cleared"`.
- `History::flush(&mut self) -> io::Result<()>`.
- **On-disk format:**
  - segments `<dir>/<first_line:020>.seg`, records `[u32 LE len][bytes]`, rolled over at `SEGMENT_BYTES`;
  - `<dir>/meta` holds `[u64 LE generation][u64 LE first_line]` and is rewritten on `clear`;
  - the oldest whole segments are deleted while the total exceeds `HISTORY_MAX_BYTES`, which advances `first_line`;
  - appends are buffered (64 KiB) and never fsynced.
- **Tail:** a `VecDeque<Bytes>` capped at `HISTORY_TAIL_BYTES`. Lines in the tail are also on disk.

**Interfaces (Produces):**
- **`fleetd --stdio [--state-dir P]`** copies stdin to the daemon socket and the socket to stdout until either side closes. If no daemon answers, it starts `fleetd [--state-dir P]` (`std::env::current_exe()`) detached: `setsid` in `pre_exec`, stdio to `/dev/null`, its own process group. It waits up to 5 s for the socket. Exit code 1 with a message on stderr if the daemon never comes up.
- **Env capture:**
  - `fleet_node::env::capture_login_env(shell: &Path, timeout: Duration) -> Option<Vec<(OsString, OsString)>>` runs `$SHELL -lic 'printf "\0__FLEET_ENV__\0"; env -0; printf "\0__FLEET_END__\0"'` with stdin `/dev/null` and parses between the markers, dropping `PWD`, `OLDPWD`, `SHLVL` and `_`.
  - `fleetd` runs it on a background thread at startup.
  - `Node::spawn` waits for it (at most until the 5 s timeout) on first use, then uses it as the env base. With no `SHELL`, it falls back to the daemon's env.
- **Skill:**

  - `fleet skill uninstall [--project [DIR]]` removes that dir.
  - `fleet skill print` writes the file to stdout.
  - `--target` is accepted only as `claude` (the default); anything else is an error naming M4.
- **`SKILL.md` content:**
  - Frontmatter `name: fleet` and a `description` that triggers on working with other agents, the fleet, spawning or messaging an agent, and reading another agent's output.

  - It says to spawn or kill agents only when the user asked.
  - It says long output should be read with `--lines` rather than in full.
