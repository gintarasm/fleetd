# 0018 — M1 protocol server and node

**Status:** accepted · 2026-11-13

**Amended by:** [0021](0021-agent-history.md) (agent history), [0022](0022-protocol-v2.md) (protocol v2: history, lag and activity events, primary client, labels), [0032](0032-daemon-restart-handoff.md) (a requested restart execs into a new binary and keeps agents; supersedes § Daemon shutdown for that case).

## Protocol

**Context:** 0006 fixes protobuf messages, length-prefixed framing, binary output frames and a version handshake; 0005 puts the terminal grid on the node so reattach costs O(screen). M1 makes these concrete for the local unix socket (`<state-dir>/fleetd.sock`).

**Decision:**

- **Wire format** (`fleet-proto`, `FrameCodec`): every frame is `[u32 BE len][u8 kind][payload]`, `len` counting the kind byte and payload; a zero length, an unknown kind or `len > MAX_FRAME` (16 MiB) is a protocol error. Kinds: `1 Hello`, `2 HelloOk`, `3 HandshakeReject`, `4 Request`, `5 Response`, `6 Event` (protobuf payloads, package `fleet.v1`) and `7 Output`, whose payload is `[u64 BE agent_id][raw PTY bytes]`, deliberately not protobuf so terminal output is never re-encoded.
- **Handshake:** the client's first frame must be `Hello` (at most 4 KiB, within 5 s). `PROTOCOL_VERSION = 1`; a mismatch is answered with `HandshakeReject { reason }` and the connection is closed, otherwise `HelloOk`. At most 64 concurrent connections; more are rejected the same way.
- **Requests:** `Request { id, kind }` (`SpawnAgent`, `ListAgents`, `Attach`, `Detach`, `SendInput`, `Resize`, `KillAgent`) are answered strictly in order by `Response { id, kind }` (`AgentInfo`, `AgentList`, `AttachOk`, `Ack`, `Error`). `Response.id = 0` was reserved for the lag notice, which protocol v2 replaced with `Event::Lagged` ([0022](0022-protocol-v2.md)). `Event::AgentExited` is pushed to every connection; for an attached agent it comes after the agent's last `Output`.
- **Terminal sizes:** `SpawnAgent` and `Resize` sizes must have each side in 1..=1000 and at most 250 000 cells (`MAX_DIM`, `MAX_CELLS`), else the response is an `Error`; in `SpawnAgent` a zero side means the default 80x24.
- **Attach:** `AttachOk { snapshot, cols, rows }` is queued before any `Output` of the new subscription, and the stream continues exactly where the snapshot ends (snapshot and subscription are taken under the lock that feeds the grid). Re-attaching replaces the previous subscription; attaching an exited agent yields its final screen and its exit event.
- **Exited agents are released:** on exit the node flushes and closes the agent's scrollback file, drops its PTY and grid, and keeps only the final snapshot bytes of the last 64 exits (`RETAINED_EXITED`, oldest evicted first), so a long-running daemon's fds and memory do not grow with the number of agents it has run. Attaching to an evicted exited agent (or one that exited under a previous daemon) yields `AttachOk` with an empty snapshot and size 0x0, followed by its exit event; it still lists from the store, and its history remains in its scrollback file. Killing an exited agent is a no-op; input and resize are errors.
- **Snapshot as ANSI:** the snapshot is a byte sequence that redraws the visible screen into a fresh terminal of the same size. A screen is drawn as `\x1b[0m\x1b[H\x1b[2J`, the grid (text, SGR attributes incl. 256/truecolor and underline colour, wide and combining characters), the saved cursor (DECSC: CUP and its pen, then `\x1b7`; omitted when it equals a fresh terminal's), the active pen, the kitty keyboard flags, the non-default modes (cursor visibility, application cursor/keypad, mouse reporting 1000/1002/1003/1005/1006, focus events, alternate scroll, bracketed paste, autowrap, origin, insert, LNM) and a final CUP; a pending autowrap (of the cursor or the saved cursor) is recreated by re-emitting the glyph under it. The saved cursor goes before the modes because DECSC/DECRC positions are absolute and origin mode is not yet on. If the alt screen is active, the snapshot first draws the primary screen the same way (its grid, pen, cursor and kitty flags; no saved cursor, since `?1049h` overwrites it, and no modes), then `\x1b[?1049h`, then the alt screen, so `?1049l` on the client shows the node's primary screen. Kitty keyboard flags are pushed (`CSI > flags u`, one stack level, popped by `fleet attach`'s `CSI < u` on exit) when non-zero; after a primary screen that pushed, the alt screen's flags are set instead (`CSI = flags ; 1 u`, also when zero), so a client already on its own alt screen ends one level deep with the alt flags. The node's grid tracks the kitty flags (alacritty's `kitty_keyboard` option) but does not answer the `CSI ? u` query, so agents are not told the unknown client terminal supports the protocol. Reading the primary screen behind the alt screen uses alacritty's public `Term::swap_alt` and back; the round trip clears the alt grid and resets its kitty flags, so the alt grid is cloned and restored and the flags re-applied (a test pins this `swap_alt` behaviour). A pending synchronized update (`?2026`) is applied first, and an escape sequence or UTF-8 character split across reads (up to 4 KiB) is appended, so the client's parser continues in step. Clients need only a VT parser, no grid format. Known limits: the scroll region (DECSTBM) is not carried (alacritty exposes no accessor, so the client starts with a full-screen region); only the current kitty keyboard flags of each screen are carried, not the stack below them (alacritty keeps the stacks private, so popping more levels than the snapshot pushed gives 0 on the client); after a resize while the alt screen is active the inactive primary's cursor and saved cursor can differ, and taking a snapshot then sets the node's primary saved cursor to its cursor (`swap_alt` back overwrites it); not carried either are charsets (also in the saved cursor), tab stops, hyperlinks and soft-wrap markers.
- **Subscriber drop policy:** each subscription is a bounded channel of 256 output chunks (`SUBSCRIBER_CAPACITY`) that the PTY reader thread only `try_send`s into, so a slow client never slows its agent or other clients. Output chunks still queued are merged up to 16 KiB (`COALESCE_BYTES`, M2a), so the queue's depth in output does not shrink with the PTY's read size (~1 KiB on macOS); per-subscription memory is bounded by about 256 x max(16 KiB, one read). A subscriber whose queue is full is dropped; the connection is told so (since v2 with `Event::Lagged { agent_id }`, [0022](0022-protocol-v2.md)), and the agent's exit event is then delivered through the connection's exit-event stream. The client must re-attach (the snapshot makes this cheap). Each connection has one writer fed by a 256-frame queue; a client that stops reading stalls only its own forwarders, which then lag out.
- **Terminal query replies** (DSR/CPR, DA, …) are answered by the node's grid and written back to the agent only while no client is attached; while one is, the client's terminal answers. Replies are written without blocking and dropped if the agent's input is full.
- **Scrollback ring:** each agent's raw output is appended to `<state-dir>/scrollback/<id>.ring`, a fixed-size file (8 MiB of data plus a 16-byte header `[u64 LE write_pos][u64 LE total_written]`, mode 0600). Appends are buffered (64 KiB) and flushed without fsync; history is best effort, the live grid stays authoritative. M1 records it; serving it to clients comes later.
- **fd budget:** a running agent holds three fds in `fleetd` (the PTY master, one duplicate of it shared by the reader thread and input/reply writes, and its scrollback file); an exited one holds none. `fleetd`'s `main` raises the soft `RLIMIT_NOFILE` to the hard limit (at most `OPEN_MAX` = 10240 on macOS), so ≥ 50 agents fit even under a 256-fd soft and hard limit.
- **Agent states:** `running`, `exited` (with exit code) and `lost`: on startup the node marks every agent still `running` in the store (left behind by a crashed or killed daemon) as `lost`, since its PTY cannot be recovered (no handoff, 0013).
- **Schema compilation:** `fleet-proto/build.rs` compiles `proto/fleet.proto` with `protox` (pure-Rust protobuf compiler) and generates types with `prost-build`, so building needs no `protoc` on the machine or in CI.

**Consequences:** a reattach costs one screen (a 120x40 snapshot is typically well under 64 KiB; a screen full of distinct truecolor attributes can exceed it) regardless of output volume. In M1 a client attached to many agents at full throughput was dropped as lagged even though it kept up (`daemon_flood50`); the 16 KiB merging queue fixed that in M2a (see Known limits), and v2's `Event::Lagged` names the agent so a client can re-attach selectively. Benchmarks for the new hot paths: `daemon_flood50_*`, `reattach_snapshot_ns`, `frame_decode_output_64x64k_instructions`, `terminal_feed_64k_instructions`, `snapshot_120x40_instructions` (`bench/README.md`).

## Known limits / follow-ups

- **Passthrough limits of `fleet attach`.** The client's terminal sees the agent's output unfiltered, so an agent that leaves the alternate screen itself (`?1049l`) drops the client out of the alt screen `fleet attach` entered, so its output lands in the client's normal scrollback (and the primary screen the snapshot drew, which went to the client's alt screen, is not shown). An agent that enables the kitty keyboard protocol (`CSI > flags u`) or xterm's modifyOtherKeys makes the terminal encode Ctrl-\\ as an escape sequence instead of byte 0x1c; `fleet attach` detaches on those too: `CSI 92 ; 5 u` with optional alternate-key sub-fields (`92:124:92`), an event type of press or repeat (`:1`, `:2`; a release, `:3`, is ignored) and an optional text field, and `CSI 27 ; 5 ; 92 ~`. The modifiers must be Ctrl alone (Caps Lock and Num Lock bits are ignored) and the key code 92, so on layouts where `\\` is not a base key only 0x1c works. A sequence split across reads is held back while it can still match and forwarded unchanged as soon as it cannot, or after 20 ms without the rest (a lone Esc key press is delayed by that much); all other input is forwarded unchanged. On exit `fleet attach` soft-resets, pops one kitty keyboard level (`CSI < u`), leaves the alt screen and resets cursor visibility, bracketed paste, mouse (1000/1002/1003/1005/1006/1015), focus events (1004), application cursor keys and autowrap; an agent that pushed more kitty levels on the client than it popped leaves the extra ones on the client's alt-screen stack. Filtering these sequences is a follow-up.
- **Lag notice lacks the agent id.** Resolved in M2a: protocol v2 replaces the id-0 notice with `Event::Lagged { agent_id }` ([0022](0022-protocol-v2.md)).
- **vte drops a character after a split UTF-8 character (upstream bug, found 2026-11-13 in M2a).**
  - **Where:** `vte 0.15.0`, `Parser::advance_partial_utf8`.
  - **Trigger:** a UTF-8 character split across two `advance` calls (two PTY reads), followed within 3 bytes by another multibyte character that is still incomplete.
  - **Effect:** vte consumes the character after the split one and drops it. Repro: `feed(b"\xce"); feed(b"\xbb \xe2\x9c\x93")` shows `"λ✓"`, so the space is lost.
  - **Cause:** the `Err` branch returns `valid_bytes - old_bytes` instead of `c.len_utf8() - old_bytes`.
  - **Impact:** the node's grid, its snapshots and history, and any client that uses vte can lose a character whenever a PTY read splits a UTF-8 character.
  - **Follow-up:** report and fix upstream, or have `Terminal::feed` hold back a trailing partial UTF-8 character until the next read.
- **Daemon CPU under a 50-agent flood.** Resolved in M2a. In M1, `daemon_flood50` (50 agents x 8 MiB, one client attached to all) dropped 45–48 of 50 subscriptions as lagged although the client kept up: with ~1 KiB PTY reads on macOS a 256-chunk queue held only ~256 KiB, about 14 ms of one agent's peak output, while the forwarders' wake-ups had 15–190 ms tails under 100 CPU-bound threads (not the agents' parsing starving them, as first assumed). Merging queued output to 16 KiB fixed it: `daemon_flood50_lagged_subscriptions` is now 0 (median of 3 floods; a single flood occasionally drops up to 4), `flood50_attached4_lagged_subscriptions` (four attached panes) is 0, and `input_echo_flood50_ns` stays well under 1 ms during the flood. The cost is memory: `daemon_flood50_peak_rss_bytes` rose from ~52 MB to ~116–176 MB (user-approved).

## Daemon shutdown

**Context:** v1 has no PTY handoff to a successor daemon (0013). Leaving agents behind when `fleetd` stops would orphan untracked processes, the stale-session leak 0013 exists to prevent.

**Decision:** Stopping `fleetd` (SIGTERM/SIGINT/SIGHUP) terminates its agents: SIGTERM to each agent's process group, up to 2 s grace, then SIGKILL (and a short wait). Exits are recorded through the normal exit path, so their rows become `exited`. An agent that still has not reported, or every agent after a daemon crash, stays `running` in the store and is marked `lost` on the next start.

**Consequences:** Upgrading or restarting the daemon ends all agents (drain-and-restart, as 0013 v1 requires); shutdown takes at most ~2.5 s. Agents that escape their process group (new session) are not reached.
